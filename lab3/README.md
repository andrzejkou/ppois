# Лабораторная работа №3. Warehouse Management System

## Назначение проекта

Консольная система управления складом на **C++17**. Проект моделирует каталог товаров, складские остатки, закупки, продажи, персонал, логистику, финансы и административные процессы.

## Состав объектной модели

- **62 предметных класса** и **15 собственных классов исключений** — всего 77 классов;
- **363 поля** в предметных классах;
- **более 100 содержательных поведений**: бизнес-проверки, расчёты и операции изменения состояния;
- **39 типизированных ассоциаций**, а также композиционные связи и связи основного складского процесса;
- отдельные заголовочные и реализационные файлы, CMake-сборка, консольное приложение и CTest.

Количество методов не следует путать с количеством содержательных поведений: геттеры и сеттеры не учитываются как уникальная бизнес-логика.

## Собственные исключения

Все исключения размещены в `h/exceptions/` и `cpp/exceptions/`. `WarehouseException` является базовым исключением; специализированные ошибки наследуются от него.

| Исключение | Назначение |
|---|---|
| `WarehouseException` | Базовая ошибка складской системы |
| `ProductNotFoundException` | Товар не найден |
| `DuplicateProductException` | Повторная регистрация товара или штрихкода |
| `InsufficientStockException` | Недостаточный доступный остаток |
| `StorageCapacityExceededException` | Превышение вместимости склада |
| `InvalidStorageLocationException` | Некорректная зона или ячейка хранения |
| `ExpiredProductException` | Истёк срок годности партии |
| `SupplierNotFoundException` | Поставщик не найден |
| `PurchaseOrderException` | Ошибка закупочного заказа |
| `InvalidOrderStateException` | Недопустимый переход состояния заказа |
| `ReservationException` | Ошибка резервирования товара |
| `InventoryMismatchException` | Расхождение при инвентаризации |
| `ShipmentException` | Ошибка отгрузки |
| `PaymentException` | Ошибка проведения платежа |
| `AccessDeniedException` | Недостаточно прав доступа |

## Консольное приложение

Главное меню разделено по подсистемам. Для четырёх основных справочников реализованы CRUD-операции: создание, просмотр/поиск, изменение и удаление.

| Раздел | Возможности |
|---|---|
| Каталог товаров | Добавление, просмотр, поиск, изменение названия, цены, категории, бренда и ячейки, удаление товара |
| Поставщики | Добавление, просмотр, поиск, изменение данных и удаление поставщика с проверкой связей |
| Сотрудники | Добавление, просмотр, поиск, изменение должности/ставки и удаление |
| Покупатели | Добавление, просмотр, поиск, изменение и удаление при отсутствии заказов |
| Запасы | Приёмка и отгрузка, просмотр доступного и зарезервированного количества |
| Продажи | Создание заказа, просмотр заказов, отгрузка |
| Закупки | Заявка, согласование, заказ поставщику, приёмка и контроль качества |
| Склад | Вместимость, заполненность и зоны хранения |
| Демонстрация | Интегрированный сценарий остальных подсистем предметной модели |

Удаление ограничено бизнес-правилами. Товар нельзя удалить при ненулевом остатке/резерве или ссылках из заказов, заявок и партий. Поставщика нельзя удалить при наличии закупочных заказов. Покупателя нельзя удалить при наличии заказов. Сотрудника нельзя удалить, если он используется как системный ответственный или в заявках.

## Сохранение данных в CSV

Приложение использует файловое хранилище без внешней СУБД. При первом запуске начальные данные загружаются из `data/demo/`. Затем приложение создаёт рабочие файлы непосредственно в `data/`. При следующих запусках загружается сохранённое состояние.

| Файл | Содержимое |
|---|---|
| `products.csv` | Товары, цена, категория, бренд, ячейка, остаток, резерв и штрихкоды |
| `suppliers.csv` | Поставщики и их активность |
| `supplier_contracts.csv` | Договоры с поставщиками |
| `employees.csv` | Сотрудники, ставки, должности и навыки |
| `customers.csv` | Покупатели и показатели лояльности |
| `sales_orders.csv`, `sales_order_lines.csv` | Заказы покупателей и позиции |
| `purchase_requests.csv`, `purchase_request_lines.csv` | Заявки на закупку и позиции |
| `purchase_orders.csv`, `purchase_order_lines.csv` | Закупочные заказы, полученные и ожидаемые количества |
| `delivery_notes.csv`, `delivery_note_lines.csv` | Накладные и строки поставки |
| `receipt_history.csv` | История приёмок и результатов контроля качества |
| `stock_lots.csv` | Партии, сроки годности и статус карантина |

Сохранение выполняется после операций меню и при выходе. Сначала данные записываются во временный файл `.tmp`, затем он заменяет основной CSV. Строковые значения экранируются по правилам CSV, поэтому запятые и кавычки в названиях не нарушают структуру файла.

Каталог `data/demo/` содержит демонстрационные шаблоны. Рабочие файлы `data/*.csv` добавлены в `.gitignore`, поэтому локальные изменения не попадают в Git, а демонстрационные данные остаются в репозитории. Чтобы сбросить состояние, закройте приложение и выполните `./tools/reset_demo_data.sh`; при следующем запуске данные будут загружены из `data/demo/`.

## Сборка и запуск

Требуются CMake 3.16+ и компилятор с поддержкой C++17.

```bash
cmake -S . -B build -DCMAKE_BUILD_TYPE=Debug -DBUILD_TESTING=ON
cmake --build build -j$(nproc)
ctest --test-dir build --output-on-failure
./build/warehouse_app
```

Путь к каталогу данных задаётся CMake при конфигурации проекта, поэтому приложение находит `data/` независимо от текущего рабочего каталога. Если проект перенесён в другое место, повторно выполните команду `cmake -S . -B build`.

## Демонстрационные сценарии

### CRUD товара

1. Откройте `Product catalog` → `Create record`.
2. Введите SKU, название, цену, порог пополнения, категорию, бренд и ячейку.
3. Вернитесь в меню и выберите `Read all records` или `Find record`.
4. Измените товар через `Update record`; удаление доступно только если товар не используется другими объектами.

### Сквозная закупка

1. В `Procurement` создайте заявку и добавьте существующий SKU.
2. Согласуйте её менеджером `EMP-MGR-01`.
3. Создайте закупочный заказ для `SUP-001` или другого поставщика с действующим договором.
4. Примите поставку, укажите доставленное и принятое количество, срок годности и результат контроля качества.
5. Принятые партии увеличивают остаток; не прошедшие проверку помещаются в карантин.

### Проверка сохранения

1. Создайте товар или измените складской остаток.
2. Выйдите через `0` — приложение сохранит данные.
3. Запустите приложение повторно и откройте каталог: запись и остаток должны сохраниться.

## Тестирование

```bash
ctest --test-dir build --output-on-failure
```

В проекте предусмотрено пять наборов CTest: основные сценарии склада, дополнительные сущности, граничные случаи, покрытие по файлам и интегрированная демонстрация доменных классов. Для проверки покрытия GCC:

```bash
cmake -S . -B build-coverage -DBUILD_TESTING=ON -DENABLE_COVERAGE=ON -DCMAKE_BUILD_TYPE=Debug
cmake --build build-coverage --target coverage -j$(nproc)
```

## Примечания

- CSV-хранилище предназначено для учебного приложения и однопользовательского запуска; оно не обеспечивает транзакции и параллельную запись, как полноценная СУБД.
- Часть вспомогательных классов демонстрируется через интегрированный сценарий, а CRUD-интерфейс пока предусмотрен для четырёх основных справочников.
- Состояния заказов и закупок восстанавливаются из файлов через публичные методы перехода состояний, а не прямую запись во внутренние поля.
- Число методов в таблицах включает конструкторы и методы доступа; требование по уникальным поведениям оценивается отдельно и не приравнивается к общему числу публичных методов.
